## 4) المصادقة والأدوار والصلاحيات

### 4.1 المصادقة
- **تسجيل دخول** باسم مستخدم وكلمة سر. التشفير: `crypto.scryptSync(password, salt, 64)` مع salt عشوائي 16 بايت، والمقارنة بـ `crypto.timingSafeEqual`.
- **الجلسات:** token عشوائي 32 بايت base64url يُخزن في جدول `Session` مع انتهاء بعد **12 ساعة**، ويُجدد تلقائيًا عند تجاوز نصف المدة.
- **إرسال التوكن بطريقتين:** كوكي `sid` بـ `HttpOnly; SameSite=Lax` **و** ترويسة `Authorization: Bearer <token>` (الواجهة تخزنه في localStorage تحت المفتاح `sid` وتستخدم Bearer).
- **Rate limiting** على تسجيل الدخول: 5 محاولات فاشلة → قفل 10 دقائق (in-memory Map).
- **شاشة إعداد أول مرة:** عند عدم وجود أي مستخدمين تظهر شاشة إعداد لإنشاء حساب المدير الأول (نقطتا API: `GET /api/setup-needed` و `POST /api/setup`).
- عند فشل أي طلب بـ 401 تُنظف الجلسة محليًا ويظهر شاشة الدخول (مع حماية من race condition بعد تسجيل الدخول مباشرة — تُتجاهل أخطاء 401 خلال أول 3 ثوانٍ).

### 4.2 الأدوار (خمسة)
| الدور | الكود | الصلاحيات |
|---|---|---|
| مدير | `admin` | كل شيء |
| مدير فرعي | `manager` | كل شيء (مع المدير يُعدان "admin" في الواجهة) |
| محاسب | `accountant` | الكتابة في: عقود، مدفوعات، حركات مالية، قروض، أقساط قروض، حسابات، قيود، ملفات |
| محصّل | `collector` | الكتابة في: مدفوعات، صيانة، ملفات فقط |
| مشاهد | `viewer` | قراءة فقط |

### 4.3 الصلاحيات الدقيقة
- كل مستخدم يمكن أن يملك حقل `permissions` JSON اختياريًا بصيغة `{"payments": true, "users": false, ...}` يتجاوز الافتراضي الخاص بدوره.
- **التحقق يتم في السيرفر داخل كل مسار API** (دالتا `canWrite(role, entity)` و `canRead(role, entity)`) وليس في الواجهة فقط.
- **الأقسام الإدارية** (شجرة الحسابات، القيود، ميزان المراجعة، التدقيق، الاستعادة، الصحة، المستخدمون) **تُخفى من القائمة الجانبية** لغير المديرين **وتُحمى في الـ API أيضًا** — الإخفاء وحده لا يكفي.
- كل عملية كتابة تُسجَّل في `AuditLog` مع (المستخدم، الإجراء، الكيان، المعرّف، التغييرات JSON، وصف عربي).

## 5) محرك القيود المحاسبية التلقائية (أهم ميزة في النظام)

ملف `src/lib/accounting.ts` — محرك قيد مزدوج يربط كل عملية مالية بقيد متوازن يُنشأ/يُحدَّث/يُحذف **تلقائيًا**:

### 5.1 أكواد الحسابات المستخدمة في القيود
```ts
const ACC = {
  CASH: '1101',        // النقد بالصندوق
  BANK: '1102',        // النقد بالبنك — الحساب الجاري
  CHECKS: '1105',      // شيكات برسم التحصيل
  RENT_INCOME: '4101', // إيرادات إيجار سكني
  MAINTENANCE: '5101', // صيانة وإصلاحات
  LOAN: '2201',        // قروض بنكية — أصل مطلوب السداد
  INTEREST: '5207',    // فوائد ومصاريف قروض
};
```

### 5.2 القواعد المحاسبية (نفذها حرفيًا)
| العملية | الشرط | القيد |
|---|---|---|
| **تحصيل إيجار** | حالة الدفعة `paid` أو `partial` | مدين: الصندوق (1101) أو البنك (1102) أو الشيكات (1105) **حسب طريقة الدفع** (cash / transfer+card / check) — دائن: إيراد إيجار (4101) |
| **تحصيل إيجار** | pending / overdue / cancelled | **لا قيد** (مستحق لم يُحصَّل) ويُحذف القيد القائم إن وُجد |
| **صيانة** | status=completed والتكلفة > 0 | مدين: صيانة وإصلاحات (5101) — دائن: الصندوق (1101) |
| **استلام قرض** | principal > 0 | مدين: البنك (1102) — دائن: أصل القرض (2201) |
| **سداد قسط قرض** | principal + interest > 0 | مدين: أصل القرض (2201) بمقدار الأصل + مدين: فوائد (5207) بمقدار الفائدة — دائن: البنك (1102) بالإجمالي (الأقساط تُسدد تحويلًا) |
| **حذف أي عملية** | — | يُحذف قيدها المرتبط تلقائيًا (وحذف القرض يحذف قيود كل أقساطه) |

### 5.3 القواعد التقنية للمحرك
- **التوازن إجباري:** دالة `isBalanced` تقارب 3 خانات عشرية (`Math.round(n*1000)/1000`) وترفض أي قيد غير متوازن أو خالٍ من السطور.
- **Upsert بالمفتاح الفريد `(source, sourceId)`**: تعديل العملية الأصلية يُحدِّث قيدها تلقائيًا (لا قيود مكررة أبدًا).
- **`ensureAccounts`:** قبل إنشاء أي قيد، تأكد من وجود الحسابات المطلوبة **وكل حساباتها الأم** في الشجرة؛ إن لم توجد تُنشأ تلقائيًا من التعريف الافتراضي — فلن يفشل أي قيد أبدًا حتى لو لم يستورد المستخدم الشجرة.
- **فشل توليد القيد لا يُسقط العملية** — يُعاد كتحذير (`entryWarning`) يظهر للمستخدم لكن الدفعة تُسجَّل.
- بيان القيد يُبنى تلقائيًا بالعربية، مثل: `تحصيل إيجار — اسم المستأجر — وحدة 5 — عن 2025-01 — مرجع 123`.
- وسوم المصدر بالعربية: `manual: يدوي | payment: دفعة إيجار | maintenance: صيانة | loan: استلام قرض | loanPayment: سداد قرض`.

### 5.4 شجرة الحسابات الافتراضية
53 حسابًا جاهزة لإدارة عقارات صغيرة بالكويت، بترتيب "الأب قبل الابن" للاستيراد الصاعد. الأنواع: أصول (1)، التزامات (2)، حقوق ملكية (3)، إيرادات (4)، مصروفات (5). أبرز الفروع: 1101 صندوق، 1102 بنك جاري، 1103 بنك توفيري، 1104 ذمم مدينة، 1105 شيكات تحصيل، 1106 مصروفات مقدمة، 1201 أراضٍ، 1202 عمارات استثمارية، 1203 مجمع الإهلاك، 1204 سيارات، 1205 أثاث، 2101 ذمم دائنة، 2102 مصروفات مستحقة، 2103 تأمينات المستأجرين، 2104 إيجارات محصلة مقدماً، 2201 قروض بنكية، 3101-3105 رأس المال والأرباح والمسحوبات، 4101-4104 إيجارات (سكني/تجاري/مستودعات/خدمات)، 4201-4202 إيرادات أخرى، 5101-5106 مصروفات تشغيل عقاري (صيانة، كهرباء ومياه، نظافة، مصاعد وسلامة، تأمين، أتعاب إدارة)، 5201-5207 مصروفات عمومية (رواتب، إدارية، رسوم حكومية، بنكية، إهلاك، متنوعة، فوائد قروض).
- زر **"إنشاء الشجرة الافتراضية"** (للمدير): ينشئ الحسابات الغائبة فقط **ولا يعدل ولا يحذف** أي حساب قائم، ويعرض تقريرًا (عدد المنشأ/الموجود مسبقًا).
- الحسابات نوعان: `group` (رئيسي لا يُسجل عليه) و `post` (فرعي يُسجل عليه).

## 6) أقسام النظام (18 قسمًا في القائمة الجانبية)

التنقل عبر `Section` state واحدة في مكوّن رئيسي واحد (لا صفحات منفصلة) — عند تغيير القسم تُحمَّل بياناته فقط. الأقسام الإدارية (7) لا تظهر إلا للمدير/المدير الفرعي.

### 6.1 لوحة التحكم (dashboard)
- **5 كروت KPI** بشارات متدرجة الألوان: عدد العمارات، عدد الوحدات، المستأجرين، العقود النشطة، المدفوعات المعلقة/المتأخرة + نسبة الإشغال (المؤجرة/الكل).
- **مؤشرات مالية مجمعة:** المتأخرات (مجموع الدفعات pending/overdue)، رصيد القروض (الأصل − المسدد، **الفوائد لا تُخصم من الأصل**)، صيانة مفتوحة، إيرادات/مصروفات/صافي الحركة من جدول الحركات.
- **لوحة الإيرادات المتوقعة** لكل العمارات (من مكتبة `calc.ts` — انظر 10).
- **جدول مقارنة العمارات:** لكل عمارة عدد وحداتها وإيرادها ومصروفاتها وصافيها.
- **جدول متأخرات المستأجرين:** لكل عقد نشط — عدد الأشهر المستحقة والمبلغ المتأخر مقابل المدفوع.
- **العقود المنتهية قريبًا:** خلال 30 يومًا أو منتهية فعلًا.
- تحميل البيانات بـ `Promise.allSettled` (فشل API واحد لا يكسر اللوحة).

### 6.2 المباني (buildings)
CRUD كامل + بحث فوري + لوحة الإيرادات المتوقعة المجمعة (6 مؤشرات: الوحدات القابلة للتأجير، الشاغرة، المؤجرة، غير القابلة، المتوقع شهريًا/سنويًا، التعاقدي، إمكانات الشواغر، الفرق ونسبته). الحقول: كود فريد، اسم، عنوان، مدينة، أدوار، عدد وحدات، قيمة دفترية، رقم ترخيص، ملاحظات.

### 6.3 الوحدات (units)
CRUD مرتبط بمبنى: رقم، دور، مساحة، نوع (شقة/مكتب/محل/مستودع)، حالة بشارة ملونة (متاحة أخضر / مؤجرة أزرق / صيانة كهرماني / محجوزة بنفسجي)، إيجار افتراضي. **حالة الوحدة تُزامَن تلقائيًا مع العقود** (انظر 13).

### 6.4 المستأجرين (tenants)
CRUD ببيانات كاملة: الاسم، الهاتف، الإيميل، الرقم المدني/القومي ونوعه، العنوان، جهة اتصال للطوارئ، **الضامن وهاتفه**، ملاحظات + رفع صورة الهوية والمستندات (تظهر معاينة مصغرة في الكارت).

### 6.5 العقود (contracts)
- نموذج إنشاء/تعديل: وحدة + مستأجر + تاريخا بداية/نهاية + إيجار شهري + تأمين + يوم الدفع + شروط + ملاحظات + خيار **تحديث الإيجار الافتراضي للوحدة** تلقائيًا.
- **تحقق صارم في السيرفر** (`lib/contracts.ts`): الوحدة والمستأجر موجودان، النهاية > البداية، الإيجار > 0، و**منع تداخل عقدين نشطين على نفس الوحدة** مع رسالة عربية تُظهر فترة العقد المتعارض.
- فلترة بأزرار chips حسب الحالة (الكل/نشط/منتهي/ملغي/مجدد) + بحث.
- كل كارت عقد يعرض: الشارة، رقم العقد، الوحدة والمبنى، المستأجر، التواريخ، الإيجار، و**الرصيد الحي**: المستحق حتى الآن مقابل المدفوع والمتبقي (دالة `contractBalance`).
- رفع **صورة العقد** (تظهر زر "عرض العقد" لآخر ملف مرفق) + معرض مصغرات لكل المرفقات.
- عند إنهاء/إخلاء العقد تُزامَن حالة الوحدة تلقائيًا.

### 6.6 المدفوعات (payments)
- تسجيل دفعة على عقد: المبلغ، تاريخ الاستحقاق، تاريخ الدفع، الشهر (YYYY-MM)، الطريقة (نقدي/تحويل بنكي/شيك/بطاقة)، المرجع، ملاحظات.
- **تصنيف تلقائي:** دفعة أقل من الإيجار الشهري تُصنَّف `partial` تلقائيًا.
- حالات بشارة ملونة: معلق/مدفوع/جزئي/متأخر/ملغي.
- زر **سند قبض** للطباعة يظهر للدفعات المسددة (مدفوع/جزئي).
- **عرض مزدوج:** جدول كامل للديسكتوب + كروت للموبايل.
- كل دفعة مسددة تولّد قيدها المحاسبي تلقائيًا (5).

### 6.7 الصيانة (maintenance)
طلبات صيانة مرتبطة بوحدة (اختياري): عنوان، وصف، تصنيف (سباكة/كهرباء/تكييف/مصاعد/مدني/نظافة/أخرى)، أولوية بشارة (منخفض/متوسط/عالي/عاجل)، حالة (مفتوح/قيد التنفيذ/مكتمل/ملغي)، تكلفة تقديرية وفعلية، مُنفّذ. عند الاكتمال بتكلفة: يُولَّد قيد مصروف تلقائيًا + **سند صرف** قابل للطباعة + رفع صور المشكلة.

### 6.8 الملفات (files)
سجل مركزي لكل الملفات: معاينة مصغرة للصور، النوع، الحجم، تصنيف بشارة (مدنية/عقد/صيانة/عام)، **مرتبط بـ** (يُحل تلقائيًا إلى اسم العقد/المستأجر/الصيانة)، تحميل، حذف، بحث.

### 6.9 الإيرادات والمصروفات (transactions)
حركات مالية عامة: تاريخ، عمارة (اختياري)، نوع إيراد/مصروف بشارة ملونة، بيان، مبلغ، حساب من الشجرة، طريقة الدفع (صندوق/بنك). لكل سطر **سند قبض أو صرف** قابل للطباعة حسب النوع. CRUD كامل + بحث + عرض مزدوج جدول/كروت.

### 6.10 القروض (loans) — تصميم متكامل
- **4 كروت ملخص:** إجمالي القروض، المسدد من الأصل، المتبقي، الفوائد المسددة.
- **كارت لكل قرض** يجمع كل شيء: اسم القرض، شارات (العمارة/نسبة الفائدة/المدة/التاريخ)، **شريط تقدم نسبة سداد الأصل** (يتحول للأخضر عند السداد الكامل مع علامة ✓)، 4 إحصائيات (أصل/مسدد/متبقي/فوائد مسددة)، وسجل أقساط قابل للطي — فيه لكل قسط: التاريخ، الأصل، الفوائد، الإجمالي، وزر **سند صرف القسط**.
- أزرار: سند قبض استلام القرض، تسجيل قسط، تعديل، حذف.
- القيد التلقائي للاستلام وكل قسط (انظر 5).

### 6.11 شجرة الحسابات (accounts) — للمدير
جدول (رقم/اسم/نوع/تصنيف رئيسي-فرعي) + إضافة/تعديل/حذف + زر استيراد الشجرة الافتراضية (5.4).

### 6.12 القيود اليومية (journal) — للمدير
- جدول بكل القيود: التاريخ، البيان (+ شارة مصدر تلقائي إن لم يكن يدويًا)، العمارة، وسطور القيد (كود الحساب + الاسم + شارة مدين خضراء/دائن حمراء).
- **إضافة قيد يدوي**: نموذج متعدد السطور (حساب + مدين/دائن) مع تحقق توازن.
- تعديل أي قيد، **حذف يدوي فقط** (قيود العمليات التلقائية لا تُحذف يدويًا).
- زر **طباعة إذن القيد** لكل قيد + زر **طباعة دفتر اليومية** للقيود المعروضة/المفلترة.

### 6.13 ميزان المراجعة (trialBalance) — للمدير
يُجمع من كل سطور القيود لكل حساب: حركات مدين/دائن + رصيد مدين/دائن، صف إجمالي، شارة "متوازن ✓ / غير متوازن" (تقريب 3 خانات)، بحث، وطباعة رسمية للميزان.

### 6.14 سجل التدقيق (audit) — للمدير
آخر 100 عملية: الوقت، المستخدم، الإجراء بشارة، الكيان، التفاصيل + بحث.

### 6.15 نقاط الاستعادة (restore) — للمدير
