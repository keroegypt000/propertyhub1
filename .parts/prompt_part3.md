
### 6.16 صحة النظام (health) — للمدير
كروت حالة (السيرفر/قاعدة البيانات/التخزين/آخر فحص) + معلومات النظام: الإصدار، نوع قاعدة البيانات، حالة التخزين السحابي، عدد المباني والعقود النشطة والمستخدمين.

### 6.17 المستخدمون (users) — للمدير

### 6.18 الإعدادات (settings)

## 8) إدارة الملفات والتخزين السحابي (`lib/storage.ts`)

- **الرفع من المتصفح:** الملف يُرسل raw body مع ترويسات `X-Filename` و `X-Category` و `X-Contract-Id/X-Tenant-Id/X-Maintenance-Id` للربط.
- **ضغط الصور في المتصفح قبل الرفع** (لتجاوز حد المنصة 4.5MB): كل صورة > 400KB تُصغَّر لأقصى بُعد 1920px وتُحوَّل JPEG بجودة 0.82 عبر Canvas (GIF يُستثنى). الحد النهائي 4MB.
- **الأنواع المقبولة:** JPEG/PNG/WebP/GIF/PDF — مع **كشف النوع الحقيقي بالبايتات السحرية** (magic bytes) وليس بامتداد الملف.
- **التخزين:** إن توفرت متغيرات R2 (R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_BUCKET) يُرفع الملف للسحابة بمفتاح `uploads/YYYY/MM/<fileId><ext>` مع **تحقق HeadObject** بعد الرفع؛ وإلا يُخزن داخل قاعدة البيانات (وضع legacy). قاعدة البيانات تحتفظ بالمرجع فقط.
- **التحميل يمر عبر API مصادق عليه** (`/api/files/[id]`) — لا روابط عامة دائمة. المفاتيح السرية على السيرفر فقط.
- حذف الملف من R2 عند حذف سجله + تنظيف الملفات اليتيمة لو فشلت قاعدة البيانات بعد رفع ناجح.
- أداة **ترحيل جماعي** للملفات القديمة من القاعدة إلى R2 (للمدير).
- `.trim()` لكل متغيرات البيئة (حماية من مسافات النسخ واللصق في Vercel).

## 9) الأمان (ملخص تنفيذي)
1. scrypt + salt + timingSafeEqual لكلمات السر.
2. جلسات بقاعدة البيانات مع انتهاء 12 ساعة وتجديد تلقائي، كوكي HttpOnly + Bearer.
3. Rate limiting على تسجيل الدخول (5 محاولات → قفل 10 دقائق).
4. **تحقق صلاحيات في السيرفر داخل كل مسار** + أقسام إدارية مخفية ومحمية.
5. سجل تدقيق لكل عملية مع هوية المستخدم والتفاصيل.
6. esc() لكل نص مطبوع، وكشف MIME بالبايتات السحرية، وقائمة أنواع بيضاء.
7. تحميل الملفات عبر API مصادق فقط (لا روابط عامة).

## 10) حسابات مالية مشتركة (`lib/calc.ts`) — مصدر واحد للحقائق
- `buildingIncomeStats`: لكل عمارة — الوحدات القابلة للتأجير (available+rented فقط؛ الصيانة تُستثنى)، الشاغرة، المؤجرة، **المتوقع شهريًا** (مجموع الإيجار الافتراضي للقابلة للتأجير)، **التعاقدي شهريًا** (عقد نشط واحد كحد أقصى للوحدة — الأحدث إذا تعددت)، إمكانات الشواغر، الفرق ونسبته، والسنوي ×12.
- `totalIncomeStats`: تجميع عام لكل المباني.
- `contractBalance`: المديونية الحية لكل عقد — الأشهر المستحقة من البداية حتى اليوم (بحدود مدة العقد، ويُحتسب الشهر مستحقًا إذا تجاوز يوم الدفع)، المستحق = أشهر × الإيجار، المدفوع = كل الدفعات غير الملغاة، المتبقي.
- `fmtKWD`: تنسيق الدينار الكويتي حتى 3 خانات عشرية بلا أصفار زائدة.
- **لا عد مزدوج أبدًا:** الوحدة غير القابلة للتأجير تُستثنى من المتوقع، والعقد النشط الواحد فقط يُحسب لكل وحدة.

## 11) نظام الألوان والتصميم (UI/UX)

### 11.1 الهوية البصرية
- **الثيم:** برتقالي/عنبري دافئ. الخلفية: تدرج `from-orange-50 via-amber-50 to-yellow-50`. الأزرار الأساسية: تدرج `from-orange-500 to-amber-500` نص أبيض وظل.
- **الكروت:** بيضاء `border-0 shadow-lg rounded-2xl`، عند الـ hover ترتقي لـ `shadow-xl` بـ `transition-shadow`. شريط ملوّن علوي بسماكة 1.5 داخل بعض الكروت (القروض) يتحول أخضر عند الاكتمال.

- **الشارات (Badges):** خرائط ألوان ثابتة لكل حالة (وحدات/عقود/مدفوعات/صيانة/أولويات/مصادر القيود) — أخضر للسليم، أزرق للتقدم، كهرماني/برتقالي للتحذير، أحمر للخطر، رمادي للملغي، بنفسجي للقروض، نيلي للمصادر التلقائية.

### 11.2 التخطيط والتجاوب
- **ديسكتوب:** قائمة جانبية ثابتة يمين `w-64` بخلفية زجاجية `bg-white/80 backdrop-blur-xl` وحدود يسارية (RTL) — شعار PropertyHub، أزرار تنقل بـ `rounded-xl` تتحول لتدرج برتقالي بظل عند التفعيل، وفي الأسفل بطاقة المستخدم (أول حرف من اسمه في دائرة متدرجة + اسم دوره) وزر خروج.

- شبكات KPI متجاوبة: `grid-cols-2 sm:grid-cols-3 lg:grid-cols-5`.
- كل قسم يبدأ بسطر عنوان + بحث فوري (`pr-9` مع أيقونة يمين) + زر الإضافة الأساسي.
- مكوّن `EmptyState` موحد (أيقونة كبيرة + نص عربي "لا توجد...") لكل قائمة فارغة.
- مكوّن `FormDialog` موحد يلف كل النماذج (Dialog بعنوان عربي وعرض مضبوط) — النموذج يستدعي `onSave` ثم `onClose`.

## 13) قواعد العمل الجوهرية (Business Rules) — انسخها حرفيًا

1. **العملة دينار كويتي 3 خانات عشرية** — كل الحسابات المالية تُقرَّب بـ `Math.round(n*1000)/1000`.
2. **منع تداخل العقود:** لا يُقبل عقد نشط ثانٍ على نفس الوحدة يتقاطع زمنيًا مع عقد نشط قائم.
3. **مزامنة إشغال الوحدة:** عقد نشط/مجدد → الوحدة `rented` (إلا لو `maintenance` فتبقى). عقد منتهي/ملغي/مُخلاً → الوحدة المؤجرة تعود `available`.
4. **الدفعة الجزئية تلقائيًا:** دفعة أقل من الإيجار الشهري للعقد تُصنَّف `partial` تلقائيًا.
5. **القيد يتبع العملية:** يُنشأ/يُحدَّث/يُحذف تلقائيًا بمفتاح (source, sourceId) — تعديل دفعة يعدّل قيدها، حذف قرض يحذف قيوده وقيود كل أقساطه.
6. **فوائد القرض مصروف وليست خصمًا من الأصل** — رصيد القرض = الأصل − الأصل المسدد فقط.
7. **الأقساط تُسدد بنكًا** دائمًا (قيد دائن على 1102)، والصيانة تُدفع نقدًا (1101)، والتحصيل حسب طريقة الدفع.
8. **فشل توليد القيد لا يمنع العملية** — يظهر تحذير فقط.
9. **ensureAccounts** ينشئ أي حساب غائب مع آبائه قبل أي قيد — النظام لا يتعطل أبدًا بسبب شجرة ناقصة.
10. **نقطة استعادة تلقائية** بعد كل عملية كتابة من الواجهة.
11. **الشجرة الافتراضية تُستورد دون تدمير** — ينشئ الغائب فقط.
12. الحسابات `group` لا تُسجل عليها قيود — الـ `post` فقط.

7. **الشجرة والقيود وميزان المراجعة** (قسم admin الثلاثي) مع seed الافتراضي.
8. **الحركات المالية والقروض** بكروتها المتكاملة.
9. **الملفات والتخزين** (رفع + ضغط المتصفح + معاينة + R2 اختياري).
10. **السندات والمستندات** (print-docs كاملًا: القالب الموحّد + المستندات الثمانية + VoucherDialog).
11. **التدقيق والاستعادة والمستخدمون والصحة والإعدادات.**
12. **الواجهة الرئيسية** (PropertyManagerApp): القائمة الجانبية للديسكتوب والدرج للموبايل، وشبكة الأقسام الـ 18 بنظام الألوان البرتقالي والمكونات الموحدة.
13. **التجاوب الكامل** موبايل/ديسكتوب لكل قسم (جدول/كروت).
14. **النشر:** vercel.json + GitHub + Prisma Postgres، ثم اختبر: إنشاء مدير → شجرة افتراضية → عمارة → وحدة → مستأجر → عقد → دفعة → **تأكد أن القيد تولّد تلقائيًا** → سند قبض يُطبع → ميزان مراجعة متوازن ✓.
